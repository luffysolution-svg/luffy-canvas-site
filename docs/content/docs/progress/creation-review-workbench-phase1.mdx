# AI 创作审核台 Phase 1

AI 创作审核台位于 `/creation`。它适合从文章、Markdown、主题或内容需求开始创作；已有成熟提示词、只需直接生图时，继续使用原有「生图工作台」。

## 核心流程

```text
原始内容与平台目标
→ 文本模型生成结构化 CreativeBrief
→ 人工修改并批准方案
→ 文本模型生成 3 个提示词版本
→ 人工编辑、对比、恢复并批准提示词
→ 明确确认后生成 2–4 个图片候选
→ 采用、反馈、单项重试或参考图续绘
→ 再次确认后插入 Luffy Canvas
```

调用生图模型前不会自动跳过方案审核和提示词审核；插入画布也必须先采用一张候选图。

## 架构与数据流

- `CreationProject` 保存原始输入、方案版本、提示词版本、全部历史生成图、候选配置、审核记录和画布插入记录。
- 文本模型返回先经过 `jsonrepair` 修复，再由 Zod 严格校验。平台、目标尺寸、宽高比和原文由应用注入，模型不能覆盖。
- 每个提示词版本都会程序化附加不可删除的硬约束块。人工编辑会生成新版本，不覆盖旧版本。
- 每个候选通过统一 image gateway 调用现有批量生图链路；候选各自保存模型、尺寸、质量和背景参数，失败项可以单独重试。
- 图片 Blob 保存在 IndexedDB 的 `image_files`，创作项目只保存 `storageKey` 与元数据。刷新后通过 `storageKey` 恢复预览。
- 插入画布使用本地持久化的幂等传输命令。目标画布完成 hydration 后在当前视区中心创建等比图片节点，并写入完整 `creationSource`。

## 使用方式

1. 在「配置」中准备一个文本模型和一个生图模型。API Key 仍按项目现有策略保存在浏览器本地，并由前端直连对应接口。
2. 打开「AI 创作审核台」，填写任务名称、平台、场景、补充要求和原始内容。
3. 点击「分析内容」，检查结构化方案的受众、核心信息、标题、主体、构图、风格、文字和禁用元素。
4. 修改后点击「保存并批准方案」，再选择 3 种优化风格生成提示词。
5. 切换、编辑或对比提示词；「保存为新版本」和「恢复旧版」都会保留完整历史。点击「批准并进入生图」只开放候选区，不会立即请求生图。
6. 在候选区选择 2–4 列，为每列选择提示词版本、模型、尺寸和质量，再点击「运行全部候选」。
7. 对结果执行采用、单项重试、问题标记、参考图续绘、保存资产或保存模板。问题反馈会进入下一轮提示词迭代。
8. 采用一张图片后点击「插入画布」，选择新建普通画布或已有画布。

## 已实现

- 明确状态机、前进、回退、取消、失败恢复和步骤重跑。
- `CreativeBrief` 严格结构化解析和人工审核。
- 原始/优化/手工/恢复提示词版本与双栏对比。
- 2–4 个候选位、不同模型参数、部分失败隔离和单项重试。
- OpenAI 兼容、Gemini、Qwen、Custom script，以及新增 OpenRouter 与火山方舟 / Seedream 调用。
- 候选采用、问题反馈、参考图续绘、资产/模板保存。
- 创作历史 localforage 持久化与图片 IndexedDB 恢复。
- 新建或指定画布的等比图片节点插入和完整生成溯源。

## 本阶段未实现

- 平台 artboard、安全区覆盖层、多规格导出和一份内容多平台适配。
- 小红书多页卡片、批量分页和 ZIP 导出。
- 科研图件契约、科研 QA、Python/R 数据图和 Agent 自动化入口。
- 画布背景图层、背景锁定和平台裁切语义。

## 已知限制

- 当前是纯浏览器直连模型接口。若中转站禁止浏览器跨域，需要配置允许 CORS 的中转站、使用自定义同源反向代理、桌面壳或本地开发代理；现有图片代理只负责下载无需额外鉴权头的 HTTPS 结果，不代理生成请求。
- OpenRouter 和 Seedream 的供应商专用扩展参数尚未开放为审核台表单；可继续使用每模型自定义调用脚本。非空 `providerOverrides` 会明确报错，不会静默忽略。
- 精确平台尺寸与供应商实际生图尺寸分开保存。Phase 1 使用供应商支持的比例生成视觉素材，精确画板与安全区由后续平台画板完成。
- 远程图片若因 CORS 无法写入 IndexedDB，仍会显示为生成成功，但在本地化前不能插入画布。
- 多标签页同时编辑同一画布仍受现有本地快照同步边界限制。
