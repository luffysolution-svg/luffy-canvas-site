# 本地 Agent 连接画布原理

浏览器不能直接启动用户电脑上的 Codex 或 Claude Code。Luffy Canvas 在本机运行 Agent，作为浏览器状态、标准 MCP 和本地 Provider CLI 之间的可信边界。

```text
Codex / Claude Code / WorkBuddy
             |
       luffy-canvas MCP
             |
      Luffy Canvas Agent
             |
      浏览器画布 React 状态
```

画布、素材和生成配置仍保存在浏览器本地；Agent 不直接操作 DOM，也不把本机登录态上传到 Vercel。

## 两个本地进程

- 普通 Agent 进程提供 HTTP、安全配对、事件流和网页工具转发。
- `mcp` 进程通过 stdio 向 MCP 客户端注册当前 Profile 允许的工具。

两个进程读取同一份 `~/.luffy-canvas/agent.json` 非敏感配置。只启动其中一个不能完成完整网页控制链路。

## 安全配对

1. Agent 默认只监听 `127.0.0.1`，生成短期、一次性 pairing code。
2. 网页 `POST /pair` 换取有过期时间、可撤销的 session token。
3. 后续 HTTP 和事件流通过 Header 或短期一次性 ticket 授权。
4. token 不进入 URL、浏览器历史、Referrer、日志或永久 `localStorage`。
5. Origin 在配对时授权；非允许 Origin 的请求会被拒绝。

旧永久 token 只保留一个版本的兼容读取和弃用警告，不继续写入新配置。

## MCP 工具如何操作画布

读取流程：

```text
浏览器快照 -> Agent 内存 -> MCP 工具 -> 客户端
```

写入流程：

```text
MCP 工具 -> Agent -> 页面 tool_call -> 网页审批 -> React store -> 工具结果
```

Profile 先过滤客户端可见工具和输入；网页再对修改、删除、生成、附件和素材写入做独立审批。MCP 客户端批准工具不等于网页批准画布写入。

## Provider Adapter

网页侧边栏通过统一 `AgentAdapter` 使用不同 Provider：

- `CodexAdapter`：会话列表、新建、恢复、删除、turn、中断、附件、流式事件和 token usage。
- `ClaudeCodeAdapter`：检测本机 CLI、发送 turn、解析流式 JSON、显示工具调用、错误和停止进程。

Provider capability 会标记真实支持范围。Claude CLI 不支持的历史恢复或附件能力会在 UI 禁用，不使用伪造历史。

通用 HTTP API：

```text
GET    /agent/providers
GET    /agent/sessions
POST   /agent/sessions
GET    /agent/sessions/:sessionId
POST   /agent/sessions/:sessionId/turn
POST   /agent/sessions/:sessionId/interrupt
DELETE /agent/sessions/:sessionId
```

请求和响应都携带 `provider`。旧 `/agent/codex/*` 与 `/agent/claude/*` 在一个兼容版本内调用同一 Adapter，并返回弃用提示。

## 部署边界

Vercel 只托管网页和必要的站点 API。Canvas Agent、Codex、Claude Code、pairing code 和 session token 均留在用户本机。

客户端配置和 Profile 详见 [MCP 接入](/docs/integrations/mcp)。
